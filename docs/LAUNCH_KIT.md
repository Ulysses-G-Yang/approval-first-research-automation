# v2.1.0 Launch Kit

## One-line description

**JS-adaptive generic crawler for authorized pages: capture DOM and JavaScript
JSON, recover through one quality-gated pipeline, and retain approval-first
repair evidence locally.**

Chinese counterpart:

**面向授权页面的 JS 自适应通用爬虫：捕获 DOM 与 JavaScript JSON，以单一
QualityGate 管线恢复字段，并在本地保留审批优先的修复证据。**

The AI Research Assistant is an optional downstream layer for normalized
crawler records and Episode artifacts; it is not the primary product or a
prerequisite for `GenericSpider`.

## Release narrative

Title:

```text
v2.1.0 - JS-Adaptive Generic Crawler alpha
```

Highlights:

- One supported extraction order: configured selector, fallback, approved
  history, Scrapling adaptive, optional LLM candidate, then empty.
- Every candidate passes the same QualityGate; LLM output cannot approve or
  persist itself.
- Optional embedded JSON and passive GET/2xx/XHR/fetch JSON captures preserve
  existing YAML and `source` paths.
- RepairEpisode v1 uses opt-in local SQLite plus content-addressed artifacts,
  with structure-only retention and secret/session redaction by default.
- `crawler benchmark --json --check-baseline` replays seven synthetic JS
  evolution families twice with no external network or real model.
- The optional Assistant consumes normalized results and evidence; it retains
  its existing `agent` command and approval boundary.

## Launch post hooks

Use one reproducible owned fixture per post.

1. **A class changed; why did extraction still pass?** Show fallback recovery
   and the matching pipeline-stage metric.
2. **Data exists only in a script or XHR.** Show `embedded_json` and passive
   `network_json` without adding endpoint requests.
3. **A non-empty candidate is still wrong.** Show QualityGate rejecting it and
   the benchmark's zero invalid-candidate acceptance.
4. **Failure is useful evidence.** Show an unrecoverable case, its Episode ID,
   artifacts, and pending human decision instead of a fabricated success.

## Release gate

Do not tag or announce `v2.1.0` until:

- the fixed PR sequence (#6, #7, captures/CLI/store, #8, #9, release commit) is
  merged with its own CI evidence;
- Python 3.12 tests, Ubuntu installed-package, Windows installed-package, and
  JS benchmark are required and green on `main`;
- the Chromium boundary suite passes on Ubuntu and Windows against its temporary
  local fixture server;
- wheel and sdist are built once, installed independently, checksum-verified,
  and the workflow-dispatch dry-run passes on the final release SHA;
- the source version is changed from `2.1.0.dev0` to `2.1.0`, then and only then
  an annotated `v2.1.0` tag is created;
- the GitHub Release contains exactly the wheel, sdist, and `SHA256SUMS.txt`,
  without PyPI publication or an overwritten release.

After release, `main` advances to `2.2.0.dev0`; the existing tag never moves.

## First-week feedback loop

- Ask users for owned synthetic evolution fixtures and unclear configuration
  steps, not third-party target credentials or private sessions.
- Track benchmark regressions, invalid candidate acceptance, fixture families,
  installation failures, and repeat contributors alongside repository traffic.
- Publish only measured behavior; Alpha proves the local pipeline and evidence
  foundation, not arbitrary real-site compatibility.
